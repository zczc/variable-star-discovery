# 分析流程与下一步

本文件是后续工作的建议方案。约 1,000 个目标的新一轮筛选尚未启动，现有脚本也未实现下述全部检查。

## 选择可以验证的目标

先利用现成 TESS 光变产品。优先选择有两个以上独立观测时段、数据质量较好、附近不过于拥挤的对象；三个时段通常能提供更多比较机会。这个策略服务于本项目的验证目标，不代表只观测一次就不能发现变星。

目标选择应记录观测区、星等范围、数据来源、已有观测次数和排除条件。不能先挑出漂亮曲线，再用它们的成功比例代表全部恒星。

较新发布、重复观测充分的样本可以作为方向，但“最新数据”不意味着“尚无人研究”。前期偏亮的少量样本不宜直接扩大后宣称有代表性。

## 获取和清理光变

保存目标 TIC ID、坐标、观测区、MAST 产品 URI、时间范围和处理软件版本。原始 FITS 保留不动，清理后的数据单独输出。

先检查质量标记、缺失值、明显跳变、数据缺口和背景变化。对比 SAP 与 PDCSAP：前者是孔径内测光，后者经过系统误差校正；校正可能改变某些真实或非真实信号，不能只信一份产品。

去趋势和异常值处理必须记录参数。真实的食、耀斑或其他短暂变化可能被过强的裁剪和光滑抹掉。

## 寻找并复核周期

Lomb–Scargle 周期图适合初筛许多重复信号；对于窄而短的食，可以另用适合这类形状的方法，例如 BLS。不同方法只是帮助找候选，不能代替物理核验。

对候选周期至少检查：原始时间序列、相位折叠图、主要竞争峰、两倍和一半周期、同一观测区前后半段，以及独立观测区。后续应估计周期不确定性，不能仅按小数位数判断精度。

跨时段折叠图相似，不自动表示多年相位完全一致。前期 TIC 458747716 的图是每个观测区分别拟合、分别折叠，不能作为多年使用单一周期保持相位的证明。

## 排除仪器异常与邻星干扰

对重点候选检查目标像素文件、测光孔径、背景、质心变化和邻星分布。比较不同孔径下的变化，并判断信号位置是否与目标吻合。

TESS 像素较大，邻近已知变星的变化可能出现在目标曲线中。即使多个观测区都出现类似周期，也可能一直来自同一颗邻星。

前期像素分析使用探索性的相干信号图，没有完成精细的仪器像响应拟合。其 `signal_peak_snr_iid_only` 使用简化噪声假设，不能直接当作最终显著性或发现概率。

## 完成查重

结合 VSX、SIMBAD、VizieR、Gaia 变星表、TESS 食双星目录、ADS 文献及必要的其他巡天资料。检索 TIC、Gaia 等别名，也检索坐标邻域；必要时处理自行和坐标历元差异。

每次查询保留来源、日期、范围、结果和是否成功。记录至少区分以下情况：

- 查询完成，找到已发表的相关变光报告。
- 查询完成，在该来源和范围内未找到。
- 查询失败或结果不完整，待重试。
- 找到候选列表或训练集记录，但其原始出处、证据和优先权仍待核实。

不能只因 VSX 缺少条目就申请首次发现归属；也不能把别人的公开候选简单转报成自己的独立发现。

## 每颗重点候选需要保留什么

| 内容 | 最低记录要求 |
|---|---|
| 对象身份 | TIC、其他目录 ID、坐标及历元 |
| 数据来源 | 产品 URI、观测区、下载日期、原始文件校验值 |
| 周期和幅度 | 算法、单位、参数、竞争周期、不确定性及参考时刻 |
| 多时段验证 | 每段数据单独结果及联合比较，不一致之处也保留 |
| 来源定位 | 像素图、邻星表、孔径比较和可能的污染解释 |
| 查重 | 目录及文献检索记录、已有候选的出处 |
| 当前结论 | 已知对象、干扰、证据不足、待复核或可准备提交 |

## 建议的下一轮顺序

1. 在整个工作空间的 Git 根目录维护私有仓库，同时管理 `doc/` 和 `repo/`；确认身份并检查待提交文件。当前原始 FITS 按用户要求一并保存，下载来源及校验清单也保留。
2. 利用已经保存的三个案例检查方法：能否重现邻星污染、多个时段近似周期，以及周期不一致。
3. 将当前硬编码脚本改成参数化流程，补上查询失败状态、分页、重试、版本记录和候选状态表。
4. 先进行少量完整验证，确认从下载到查重都能执行，再逐步扩大到约 1,000 个有明确选择条件的目标。
5. 保留各阶段数量和淘汰原因，从最好的少量候选开始逐颗完整检查。
6. 有证据充分且未找到先前报告的对象后，整理一份可审核的 VSX 资料；是否正式提交由用户决定。

目前无需承诺新增数量。更有价值的第一轮结果，是一份可检查的候选清单和明确的排除原因，即使最后没有达到新发现标准。
