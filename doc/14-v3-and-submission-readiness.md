# 第三版改进与提交条件

更新日期：2026-11-11。尚无确认的新发现，尚无可以正式提交的候选。未知目标筛选保持暂停。

## 怎样才算可以用了

要区分筛选工具验收和单颗变星投稿。VSX 审核的是具体对象及证据，没有要求提交者的软件在某个测试集达到统一准确率。

本项目按用户要求先验证识别能力。沿用[识别能力验证](09-validation-first.md)的目标：在预先限定的周期、数据质量和变星类别内，独立正例的检出率和最终周期正确率分别至少 90%，报告置信区间、分类别结果和全部未检出或弃选的对象。计划使用约 100 颗独立正例，不能用同一颗星的多个观测时段充数。

实测反例的误报率，单侧 95% 置信上限应不超过 1%。在独立二项样本且零误报的理想条件下，需要至少 299 个反例。这是项目自己选择的统计目标，不是 AAVSO 规定；有误报、样本相关或标签不可信时，不能照搬这个数字。反例必须是在指定波段、精度和时间尺度下有依据的无变光或干扰对照，不能仅凭目录中没有变星标签。

程序还应保留来源疑点、周期歧义和失败记录，不能靠把所有难题都交给人来获得漂亮的正确率。实际总体中变星很少时，即使误报率低，候选仍可能有很多假信号，所以通过这些指标之后仍要人工复核。

## 一颗候选什么时候能准备投稿

以下是我们逐颗核验的清单。[官方指南](https://vsx.aavso.org/index.php?view=about.notice)于本日重新获取，[页面快照与下载记录](sources/vsx-guidelines-2026-11-11/receipt.json)保留在仓库中。

| 要回答的问题 | 可检查的材料 | 当前缺口 |
|---|---|---|
| 是哪颗星？ | Gaia 等来源的准确坐标、坐标历元与自行、TIC/其他编号的交叉识别，避免串星 | 重点新候选尚未完整核验 |
| 亮度真的重复变化吗？ | 原始时间序列、质量处理记录、多个观测时段的重复证据，并排比较 SAP 与 PDCSAP | 已有计算工具，独立总体表现未通过验收 |
| 变化确实来自这颗星吗？ | 星图、邻星信息、食事件差分图、不同孔径或更高分辨率观测，解释剩余混光风险 | 只有基础定位；尚未完成精密定位误差和未分辨邻星排查 |
| 周期与类型有依据吗？ | 比较半周期、一倍、两倍及其他别名；合理分类，给出周期、历元、误差和仍存的竞争解释 | 半/倍周期有改进；正式误差、联合拟合与分类仍缺 |
| 亮暗变化是多少？ | 最大/最小星等及波段，或官方 IV.c 允许的有来源目录星等加另一波段实测变幅 | 现有相对通量不能直接冒充标定星等 |
| 有没有人已经报告？ | 最新 VSX、SIMBAD、Gaia/巡天目录及相关论文检索，追溯所有先前发现线索 | 完整查重未完成；查询失败不能算通过 |
| 别人能检查并找到对象吗？ | 自行分析的光变/相位图、必要的定位图、引用、参数与数据来源，图中标注单位和波段 | HTML 和草稿导出已有，单星证据包未补齐 |

多时段检验、正式周期误差、默认准备定位图等是本项目为这类 TESS 候选设置的审查要求，不把它们全部说成 VSX 对所有对象逐项统一强制的规则。官方要求周期数据挖掘提交尽可能完整，含位置、类型、最大最小星等及波段（或适用的替代方法）、周期、历元和支持证据；存在混淆风险时应给定位图。

TESS 的 BTJD 通常表示 BJD_TDB−2457000，不能加回常数就写成 HJD。提交前要核实表单所需的时间表示，给出正确转换与原始时间标准。已实现的导出器只准备本地草稿，不发送任何资料；内部“可供人工提交”状态也不等于 VSX 接受。

第一次只需完成一颗证据清楚的对象。官方还规定，新账号的首个对象获批前只能提交一个。发现者署名根据实际贡献和先前发表情况填写，不能从 GitHub 账号自动推断。

## 本轮做了什么

第三版新增独立入口 `vstar review-v3`，保留第二版和原批量运行。规则先冻结，再重跑已有全部开发资料。

- 支持三倍、四倍至八倍的整数周期关系，避免重复形状被列成多个独立周期。同一个周期峰内仍选择拟合更好的结果。
- 扣除主要周期形状后，检查另一个周期是否还能预测残余变化。要求它在每个时段至少解释原始加权变化量的 5%，减少弱旁峰造成的弃选。这个开发阈值可能漏掉弱的真实第二周期，不是物理分类或显著性证明。
- 若不同时段分别偏向一倍、两倍等整数周期，保留重复变化，暂不选择最终周期。不能让平均得分掩盖时段之间的分歧。
- 对观测缺口造成相位覆盖不足的窄食候选，逐次留出一个循环，用其余循环预测；至少三次留出的循环得到支持，且总预测改善和训练覆盖达标。负分与不完整循环仍留在总分中，不编造缺失的食事件。

完整规则见[v3 冻结协议](../repo/benchmarks/v3-protocol-v01.json)。所有分数共用了周期搜索资料，只是开发诊断，不是“为真实变星的概率”。

原来的 W UMa、RZ Cas、U Sge、RT Aur、SZ Lyn、RS Boo 六颗独立测试星，本轮已用于调试，因此转为开发样本。原始第二版独立测试结果保留不动；重跑改善不能叫独立准确率提升。

## 实际结果与未解决问题

[36 个原开发案例](../repo/benchmarks/mixed-v04/index.html)中，34 个完成、2 个不可用，保留原分母；[原 6 星测试组](../repo/benchmarks/former-pilot-v3/index.html)全部完成。合计 42 个案例、82 段观测，没有分析运行错误。这不是 42 颗独立真实恒星。

| 4 个模拟平滑周期 | 检出 4，最终周期正确 2 | 检出 4，最终周期正确 4 |
| 4 个模拟深浅食 | 检出 3，最终周期正确 1 | 检出 4，最终周期正确 4 |
| 12 个模拟噪声、4 个漂移 | 周期误报 0 | 周期误报 0 |
| 2 个模拟等深食 | 亮度周期正确，轨道歧义保留 | 保持原判断 |
| 3 个模拟仪器周期 | 全部进入来源复核 | 保持原判断 |
| 原 3 颗可用已知星 | 3 颗检出，TU Her/RR Lyr 选对，AI Vel 有歧义 | 保持原判断；AI Vel 的竞争周期在残余检查后仍有证据 |
| 原 6 星测试组 | 检出 5，最终正确 3、选错 1、未选出 2 | 检出 5，最终正确 3、选错 0、未选出 3 |

6.2 天模拟窄食的两时段，原来交替循环预测的得分只有约 0.024、0.023，训练覆盖率约 57%、65%。逐次留出循环后，总预测改善约 0.609、0.691，最低训练覆盖约 100%、84%，分别有 4、3 个留出的循环达到预测要求。数值支持本次漏检来自分组遇到缺口的影响，不代表所有窄食问题都解决了。

SZ Lyn 从弃选改为约 0.12053546 天，与参考相符。U Sge 的错误双周期改为保留歧义；当前显示的约 6.76059 天仍只是竞争候选，不是确认周期。W UMa 原来最终选对，现在因两个时段分别偏向约 0.33359 与 0.16681 天而弃选，这是明确退步，保留在结果中。不能只报道 SZ Lyn 和 U Sge 的改善。

RT Aur 仍漏检，其中一段仅约 7 天，覆盖不足；另一段也未达到预测要求，不能把漏检全部归因于短时段。尚未实现基线与周期的联合拟合。两个真实污染案例继续保留疑似污染的像素证据，没有变成目标发现。

64 项软件测试通过，含谐波选择、残余中第二周期、互补缺口、孤立单次变暗、跨时段周期分歧和来源疑点保留。软件测试与开发结果均不能证明真实人群中的误报率。

## 接下来按什么顺序做

先复核第三版留下的错误：对 U Sge 的两种周期，比较逐次食的时间、深度与形状，并检查基线和产品处理是否改变判断；对 RT Aur 检查缓慢基线与周期信号一起拟合的方法，不能把所有问题都归咎于其中一段观测短。

随后建立有可信标签的实测反例，并在真实观测噪声中注入信号。冻结规则后，用没有拿来调试的新对象作独立测试。达到项目目标后，再从已有候选中选少量做来源与查重；遇到证据清楚且尚未发表的对象，补测光、历元和完整图表，准备第一份 VSX 草稿。

目前无法给出“再运行几天就能投稿”的可靠日期。算法优化、反例标签质量、候选是否已有研究，以及混光能否排除，决定了还要补多少工作。可以按上述检查项判断进度，不以代码写完或某次测试全过当作投稿条件。
