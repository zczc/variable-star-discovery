# VSX、发现者与命名

规则核对日期：2026-11-11；[本次官方页面快照](sources/vsx-guidelines-2026-11-11/notice.txt)。正式提交前仍应重新查看 [VSX 官方指南](https://vsx.aavso.org/index.php?view=about.notice)。

## 能用公开数据提交吗

可以。VSX 接受通过公开巡天数据挖掘得到的新变星，但要求提交者完成实际分析，例如周期测定、分类和证据图表。官方说明，对这类提交会严格检查，直接重复已有网站的信息不够。

“目录里没找到”和“首次发现”之间还差文献查重。官方明确提醒，近期论文可能尚未导入 VSX；如果别人已经发表，就不能因为自己先补录而取得发现者归属。

## 需要准备的内容

对本项目的周期变星候选，应准备：对象坐标和标识、变星类型及不确定性、最大和最小星等及波段、周期、参考历元、查找星图、相位图、观测数据来源和必要参考文献。

同时保留支撑这些字段的多观测区比较、邻星污染排查和查重记录。分类不明确时按证据表达，不能为了提交而强行确定物理类型。

公开 TESS 通量不能直接充当标准波段的最大、最小星等。需要按实际测光定义处理，并清楚注明使用的波段、标定和幅度方法。

如果无法给出同一波段中准确标定的最大、最小星等，官方指南第 IV.c 节允许在适用情况下提供有来源的目录星等，以及另一波段的实测变幅。两者的来源和波段必须分开标明，不能将两种波段的量拼成虚假的最大、最小星等。

## 分析报告能直接提交吗

本项目已经实现 HTML 分析报告和本地 VSX 草稿导出器。报告用于筛选与复核，导出器检查缺项、整理人工填写表单所需的材料；它们没有替任何候选补齐科学证据。目前没有可供正式提交的对象。

最终应另行生成 VSX 提交材料包：按 New Star Form 整理字段、参考文献和备注，另附自行分析得到的相位图等证据。HTML 页面、内部 JSON 或整个压缩包不是已经核实可直接导入 VSX 的格式；提交时仍需填写表单并按要求上传附件。

| 内容 | 官方要求或说明 | 本项目的处理目标 |
|---|---|---|
| 身份 | 准确坐标及巡天中的对象编号；坐标误差超过约 1 角秒不受推荐 | 核对标识、坐标来源、自行及历元，不仅使用附近条目 |
| 测光 | 最大和最小星等及波段，或符合 IV.c 条件的目录星等加独立变幅 | 记录标定来源及变幅定义，不能将相对通量直接标为标准星等 |
| 周期与历元 | 周期变星需要周期和参考历元；食双星通常用极小、脉动星用极大时刻 | 记录事件定义和时间标准；周期误差与竞争周期作为额外验证证据 |
| 时间表示 | 指南的历元示例要求 HJD | 保留 TESS 的原始时间元数据，核对当前表单要求及必要转换；不能给 BJD 加常数后直接称为 HJD |
| 图表 | 支持变光的图；周期目标提供自行分析的相位图，避免仅重复巡天网站现成图 | 生成有单位、波段和明确标注的图，星等图亮端朝上；多来源数据可区分 |
| 定位图 | 存在混淆风险等情况下应提供，标注北、东和比例尺，使用 PNG/JPEG/GIF | 本项目默认准备定位图，避免混淆；普通像素热力图不自动等于合格定位图 |
| 新颖性和来源 | 检查既有目录及论文，提供巡天和相关工作引用 | 保存检索记录及未解决线索，查询失败不算查重完成 |

指南第 V.d 节明确讨论了 TESS：通常使用 PDCSAP，但要防止过度校正抹掉或改变信号，必要时使用 SAP。TESS 的邻星混光也会影响来源判断和变幅，不能只完成字段填写而忽略这些问题。

导出器已经生成字段清单、参考文献、备注和内部检查结果，并收集人工提供的图表附件。完整的相位图、光变图、定位图及其科学依据仍需对具体对象核实。缺关键数据、存在未解决污染或先前发现线索时，继续标为草稿并列出缺项，不标为可提交。内部检查通过只意味着按项目检查项准备齐全，不能保证审核接受。

提交者和发现者信息按用户提供的真实署名与贡献填写，不从 GitHub 账号名自动推断。正式提交仍按用户的明确指示执行。

## 审核一般多久

官方指南说，材料准备充分、变光证据明确的提交，往往可以在几天内批准，具体取决于审核工作量。审核由志愿专家负责，没有承诺固定处理时限。

如果需要补充或修正资料，审核人会联系提交者，处理时间会相应延长。指南没有提供可以用来估算所有投稿平均等待时间的统计数据。

新用户在首个提交获批前只能提交一个对象。一般用户每周最多提交五个；系统性的大批发现，官方鼓励通过期刊发表。

指南还规定，被要求修改但两个月内仍未接受的提交，以及保留两个月的草稿，可能被系统删除。这里的 60 天是清理规则，不是正常审核周期或保证上限。

## 发现者记录意味着什么

有可能在目录条目、参考文献或发表的发现报告中留下发现者信息，具体以实际记录和归属规则为准。必须证明发现具有新意，并正确引用公共数据、软件和已有工作。

提交账号不自动等于发现者。使用别人已经发布的候选或论文资料时，不能把自己的复核工作写成对方发现的首次归属。

VSX 官方提醒，普通变星发现通常不会带来很多公众关注。这里追求的是可查到的科学贡献记录，不应把目录收录说成正式授奖。

## 可以给恒星命名吗

新变星通常继续使用已有目录编号，或后续获得按规则分配的变星名称。发现者记录不自动附带自由命名权。

系统性搜索有时可以采用一致的项目标识或编号，但官方指南对命名有规则；它们不是自动获得国际天文学联合会批准的正式名称，后续也可能被替换。不能承诺恒星会以用户姓名命名。

## 从发现到提交

目前本项目没有提交记录。先完整分析一颗候选、排查已有发现、准备可审核的图表和字段，再由用户决定是否提交。若收到反馈，应保存修改过程和最终接受内容，再据此描述成果。

## 本项目什么时候可以提交

见[验收与提交条件](14-v3-and-submission-readiness.md)。独立测试的 90% 正例目标、299 个零误报反例条件属于项目的筛选工具验收设计，不是 VSX 投稿门槛。单颗候选经过充分人工核验，即使筛选器并不完美，也可能具备投稿条件；本项目仍按用户要求先验证识别能力。
